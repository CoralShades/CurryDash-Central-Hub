## Description

To ensure data integrity and prevent accidental loss of historical records, we are removing the ability for vendors to permanently delete packages. Instead, the workflow will shift to a **Toggle (Enable/Disable)** system. Additionally, the UI needs to be updated to separate active and inactive items to keep the primary dashboard clean.

### UI/UX - List Views

- **Tabbed Navigation:** Implement a tabbed interface on the Packages Management screen:
  - **Active Items Tab (Default):** Displays all items where `is_active = true`.
  - **Inactive Items Tab:** Displays all items where `is_active = false`.
- Remove 'Delete' action from the list views.
- **Empty States:** Add appropriate empty state illustrations/text for both tabs (e.g., "No inactive items found").

### Frontend Logic

- When an item is toggled to **Inactive**, it should immediately move from the Active list to the Inactive tab.
- When an item is toggled to **Active**, it should return to the Active list.

---

### Acceptance Criteria

- [ ] Delete button/action removed from packages in the Vendor Portal.
- [ ] Marking an item as inactive should move said item into Inactive items list view.
- [ ] Marking an item as active should move said item into Active items list view.
- [ ] Both Active and Inactive tabs should contain current list view columns, actions (minus delete button) and filters:
  - **Columns:** Item number, Image, Name, Base price, Status, Actions
  - **Filters:**
    - Active tab: Search field (text), Status picklist (Active, Draft), Reset button
    - Inactive tab: Search field (text), Reset button
- [ ] Packages with the status 'Draft' should remain in active column.

> **Note:** Delete action changes are for Vendor portal only. Admin users should still retain ability to permanently delete packages from admin portal.
