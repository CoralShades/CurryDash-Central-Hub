---

#### Description

**Order Status Timeline Screen** – _Displays the step-by-step status of the current order._

1. **Header:** Show order identifier like “Order #1234” and maybe the restaurant name or logo (e.g., “Pasta Palace Order”). Also a close/back button in case user navigates away. Possibly an info icon to view order details.
2. **Status Summary:** At the top, a bold line saying **“Estimated arrival: 6:45 PM”** (or “\~10 min remaining”). Maybe include a dynamic element like an updating time or a phrase “Arriving in 10-20 min”. This is usually highlighted in a larger font or with an icon (clock or delivery scooter icon).
3. **Progress Timeline:** A vertical list of steps with statuses checked off:

    1. **Order Placed** – (✓ completed)
    2. **Restaurant Accepted** – (✓ if done, or loading...)
    3. **Food is Being Prepared** – (current step, maybe a spinner or highlighted icon like a chef hat)
    4. **Driver Picked Up Order** – (next step, greyed out if not reached)
    5. **Out for Delivery** – (greyed if future, or active if in progress with a moving icon)
    6. **Delivered** – (final step, not yet checked until done).  
      Use icons for each step (e.g., a checkmark or dot for placed, a cooking pot for prepared, a bike or car for out for delivery, a home for delivered). The current step might be highlighted in brand color or bigger icon. Completed steps have a checkmark and are dimmed to indicate done. Future steps are greyed. This timeline gives the user a clear understanding of where the order is[baymard.com](https://baymard.com/ecommerce-design-examples/63-order-tracking-page#:~:text=%2A%20Our%20large,commerce%20site).
    
4. **Driver Info:** When the order is picked up, details of the courier are often shown. We can include a placeholder section (even if earlier steps not reached yet) like:
5. Driver: **John D.** (with maybe a small avatar if available)
6. Vehicle: “Red Toyota Corolla” or a bike icon depending on delivery method.
7. A button or link **“Contact Driver”** (to call or message) and **“Contact Support”**. These can be small buttons/icons (phone icon, chat icon). Early in the timeline, this might not be active until driver is assigned.
8. **Design/Style:** Use a **card or panel style** for the timeline, separate from background. Possibly a light background with the timeline connector line running down. The brand’s accent color (maybe yellow or blue) can indicate the current status icon. For example, a yellow highlight for “Being Prepared” step currently. Use checkmark symbols (✓) or filled icons for completed steps. This should be very user-friendly at a glance – think of how Instagram stories have a progress bar, similarly here we have a progress timeline. The visual contrast between completed (maybe green check or just checkmark) and pending (grey) should be clear. Additionally, emphasize the ETA at top in bold or colored text (perhaps green or the primary color) because that’s what users care about most[baymard.com](https://baymard.com/ecommerce-design-examples/63-order-tracking-page#:~:text=%2A%20Our%20large,commerce%20site).
9. **Responsive:** On a small mobile, the timeline might take the full screen length, user scrolls to see further steps or driver info. On a large phone or desktop, it could all fit without scrolling. The map (if included inline) might be smaller on mobile; on desktop could be side by side with timeline. For our scope, likely vertical stacking on mobile.

#### Description

**Order Completion & Feedback** – _After delivery, order marked complete and request feedback._

1. **Delivered Confirmation:** Once the timeline reaches delivered, show a message: “✅ Delivered – Enjoy your meal!” perhaps on the tracking screen or as a separate final state screen. Could reuse the Order Confirmation style but tailored to delivered status. Maybe display the actual delivery time (“Delivered at 6:50 PM”).
2. **Feedback Prompt:** Many apps ask for a rating or tip at this stage. We include:
3. **Star Rating component:** e.g., “Rate your experience” with 5 stars to tap (or a scale 1-5).
4. **Tip selection:** If tipping via app is allowed after delivery, present options like preset buttons (“No Tip, 10%, 15%, Other”) or a field. This depends on the payment flow; some do pre-tip. We can include a simple slider or buttons: e.g., “Add Tip: $0, $3, $5, Other”.
5. **Feedback text (optional):** A field “Any feedback for the restaurant or driver?” which could be a short text input.
6. **Submit Button:** “Submit Feedback” which would finalize the post-order process.
7. **Design/Style:** Keep this short and sweet. Use friendly language and maybe small graphics (like a thumbs up or smiley) to encourage rating. The stars can use the brand’s accent color (e.g., yellow stars are common, which conveniently is in our palette). Tip buttons can be lightly styled (perhaps outline buttons). It should feel like a natural extension of the app – matching font and spacing – but also distinct that this is a post-action. If user chooses to skip, maybe a “Skip” link.
8. **Responsive:** No major difference; on desktop the prompt might appear as a pop-up. On mobile, it’s a full screen or in the tracking screen once delivered.

#### Description

**Description:**

Design and prototype the **Menu Management** interface for **CurryApp** sellers, allowing them to create, edit, and manage food items, including scheduling availability by day and time of the week. The system should support individual menu items as well as bundled food combinations.

---

### **Scope of Prototype**

#### **1. Menu Management Dashboard**

* View a list of added food items and bundles
* Item actions: **Add New Item**, **Edit**, **Delete**, **Duplicate**
* Status indicators: **Active**, **Unavailable**, **Scheduled**
* Modular cards or list layout for easy scanning

#### **2. Add/Edit Food Item Form**

**Fields:**

* Item name
* Description
* Price (with currency selector if needed)
* Image upload
* Portion size/unit
* Dietary tags (e.g., vegetarian, spicy, halal)
* **Save & continue** button with validation and unsaved change alerts

#### **3. Availability Scheduler (Key Focus)**

* UI for defining item availability by **day and time of the week**
* Controls:

    * Checkbox/toggle for each day (Mon–Sun)
    * Time slot picker for each selected day (e.g., 11:00 AM – 2:00 PM)
    * Option to apply the same schedule across multiple days
    * Preview of current active time slots
    
* Prevent overlapping time slots and conflicting inputs

#### **4. Food Bundles**

* Ability to create **food bundles** composed of:

    * A defined number of **main food items**
    * A defined number of **side items**
    
* UI for selecting from existing menu items to include in a bundle
* Set bundle name, price, and optional description
* Same availability and dietary tagging system as individual items
* Bundle actions: Add/Edit/Delete, similar to regular items

#### **5. Optional Enhancements (For Future Releases)**

* Add-ons for menu items (e.g., extra spice, side dishes)
* Quantity limits or per-day stock caps

---

### **Design Considerations**

* Clean, modular layout for managing individual items and bundles
* Mobile-friendly scheduling interface
* Prevent conflicting time inputs or empty states
* Clear system feedback (e.g., “Saved”, “Unsaved Changes”, “Schedule Updated”)
* Intuitive visual hierarchy for:

    * Editing food item details vs editing availability schedule
    * Distinguishing between individual items and bundles
    

---

### **Deliverables**

* Wireframes for:

    * Menu list screen (showing both items and bundles)
    * Add/Edit item modal/page
    * Weekly availability scheduler component
    * Bundle creation flow
    
* Interactive prototype (preferably in **Figma**)
* UX notes covering:

    * Handling overlapping schedules
    * Marking and displaying unavailable items
    * Differentiating food bundles visually
    * Accessibility considerations

* Mobile-optimized and responsive layout
* Emphasis on clarity and speed for busy sellers
* Use of badges, color tags, or icons for quick status identification
