## Description

As Curry Dash moves to a **Pre-paid Scheduled Only** model, we must ensure that customer funds are not held indefinitely if a vendor is unresponsive. If a vendor does not "Accept" a scheduled order within **24 hours of the order being placed**, the system must automatically cancel the order and trigger a full refund.

---

### Technical Requirements

#### 1. Automated Cancellation Worker (Cron Job)

- **Frequency:** The job should run every 30-60 minutes.
- **Logic:**
  - Query all orders where `Status = 'Pending'`.
  - Filter for orders where `created_at` is > 24 hours from the current timestamp.
  - Update `Status` to 'Cancelled' with Reason: `Vendor Unresponsive`.

#### 2. Payment Refund Integration

- **Action:** Trigger the Refund API for the respective payment provider.
- **Requirement:** Ensure the refund is processed for the **full amount** (Base price + Delivery + Service fees).
- **Validation:** The order status should only move to `Cancelled` once the Payment Gateway returns a `Success` response for the refund initiation.

#### 3. Multi-Channel Notifications

- **To Customer:** Push notification & Email: _"Unfortunately, [Restaurant Name] was unable to confirm your scheduled order. A full refund has been initiated and should appear in your account within 3-5 business days."_
- **To Vendor:** Alert: _"Order #[ID] has been auto-cancelled due to inactivity. Please ensure timely acceptance to maintain your store rating."_

#### 4. Scheduled Order Safety Buffer

- **Edge Case:** If an order is placed for "Tomorrow" (less than 24 hours away), the auto-cancel logic should ideally trigger **2 hours before the scheduled pickup/delivery time** if still unaccepted, to allow the customer time to find an alternative.

---

### Acceptance Criteria

- [ ] Any pre-paid order older than 24 hours without vendor acceptance is moved to `Cancelled`.
- [ ] Refund is automatically triggered via the payment API without manual intervention.
- [ ] Customer receives an immediate automated apology notification.
- [ ] Vendor "Response Rate" metric is updated (internally) to reflect the missed order.
- [ ] **Regression Test (Web/Mobile):** Verify that the "Order History" correctly shows the status as "Cancelled - Vendor Timeout" and the refund details are visible to the user.
